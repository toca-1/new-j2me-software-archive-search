UNIFIED J2ME ARCHIVE SEARCH - GITHUB PAGES STARTER
=================================================

SOURCE CSV ALREADY GENERATED IN YOUR UBUNTU VM:
  ~/Downloads/j2me-search-index-with-parts.csv

1. Extract this starter ZIP in Windows into your VirtualBox shared folder,
   e.g. into a new folder named 'j2me-site'.

2. In Ubuntu, run (change the target directory if your shared folder differs):

   python3 /media/sf_share/j2me-site/build_site.py \
      --input ~/Downloads/j2me-search-index-with-parts.csv \
      --out /media/sf_share/j2me-site \
      --expected-count 536025

   The converter validates rows and writes the website's compact data/ folder.

3. On Windows, install GitHub Desktop if necessary, and CLONE your EXISTING
   public repo toca-1/unified-j2me-archive-search.

4. Copy all starter contents (INCLUDING the generated data/ folder, assets/,
   index.html, build_site.py, j2me_fetch.py, .nojekyll) into the cloned repo.
   Hidden .nojekyll matters. You can also replace the initial README.md with
   the provided documentation. Do not put the full original CSV in the repo.

5. In GitHub Desktop, commit and push to main.

6. In the GitHub repository Settings > Pages: Deploy from branch, main, /(root).
   The intended public address is:
   https://toca-1.github.io/unified-j2me-archive-search/

7. Test both modes with known hashes and filenames. The helper script's
   offline volume logic is tested, but fetching from Internet Archive should
   additionally be checked end to end before announcing the project publicly.

The ZIP contains a tiny example/sample.csv for local experiments only, not
real full website data. See README.md for methodology and limitations.
